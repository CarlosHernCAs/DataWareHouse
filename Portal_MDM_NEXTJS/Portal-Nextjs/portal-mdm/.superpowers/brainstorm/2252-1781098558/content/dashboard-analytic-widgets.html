  • Sistema y ETL solo en /notifications

Concepto central: workspace analítico personal

El dashboard es el lienzo de trabajo del analista. Cada widget es una visualización que él mismo configura apuntando a una vista analítica del DWH — tablas de Gold o vistas predefinidas en el backend — eligiendo dimensiones, métricas, filtros y rango de fechas.

No es un query builder libre (eso sería Option B). Es un configurador de widgets: el analista elige qué graficar (tabla/vista), cómo (tipo de chart), y con qué datos (dimensiones + métricas + filtros). El backend expone vistas analíticas parametrizables — no SQL directo.

Vistas analíticas del DWH (backend expone estas, no SQL libre)

El backend define un catálogo de vistas parametrizables que los widgets pueden consultar. El analista elige cuál vista y con qué parámetros — nunca escribe SQL. Esto protege el DWH de queries ad-hoc pesadas.

Ejemplos de vistas iniciales a crear en el API:

vw_cosecha_mensual vw_rendimiento_zona vw_cosecha_variedad vw_proyeccion_anual vw_correlacion vw_resumen_periodo
