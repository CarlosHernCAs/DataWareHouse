Arquitectura Python-first para Charts

FastAPI genera · Next.js renderiza · Distribución real de responsabilidades

Por qué Python para charts es la decisión correcta
🐼
pandas + numpy
Agregaciones, pivots, resampling y cálculos sobre DataFrames directamente desde SQL Server — 10× más rápido que hacerlo en JS.
📊
Plotly — charts interactivos
Genera JSON de figura Plotly en el servidor. El frontend solo renderiza con react-plotly.js. Zoom, hover y tooltips nativos.
🔮
statsmodels / Prophet
Forecasting real (ARIMA, Holt-Winters, Prophet) imposible de hacer bien en JavaScript. El analista obtiene proyecciones estadísticas reales.
⚡
Sin colapso del frontend
El browser no procesa datos. Next.js solo recibe JSON de figura lista para renderizar. El peso está donde debe — en el server.
🔒
DWH protegido
Python controla qué queries se ejecutan y con qué límites. El analista nunca toca SQL directo. Queries optimizadas con pandas.
🔁
Reutiliza el backend
El FastAPI del proyecto ya existe. Solo se agregan endpoints de analytics. Sin nueva infraestructura, sin nuevo servicio.
Arquitectura en capas
🖥️ Frontend — Next.js (portal-mdm)
Solo se ocupa de UI: grid drag & drop, modal de configuración de widget, y renderizado del JSON de figura que devuelve Python. Cero procesamiento de datos.
dnd-kit (drag & drop) react-plotly.js (render) Widget config modal Layout persistido Server Component prefetch
↕
POST /api/analyst/widget · { vista, tipo, ejes, filtros } → { plotly_figure_json }
🔗 API Route — Next.js proxy
El route handler de Next.js reenvía la petición al FastAPI con el token de sesión del usuario. Sin lógica de negocio aquí.
app/api/analyst/widget/route.ts server-fetch.ts (existente) Pasa JWT → FastAPI
↕
HTTP interno → FastAPI /analyst/widget
🐍 Backend — FastAPI (Python)
Aquí ocurre todo el trabajo: consulta al DWH con pandas, transformación de datos, generación de la figura Plotly, y forecasting si aplica. Devuelve un JSON de figura Plotly listo para renderizar.
pandas plotly statsmodels prophet (forecast) sqlalchemy numpy GET /analyst/views (catálogo) POST /analyst/widget (figura)
↕
SQLAlchemy → SQL Server

Vistas analíticas de la capa Gold expuestas al backend. El analista nunca llega aquí directamente.

Ganancias de esta arquitectura

  • El browser nunca procesa datos — imposible que colapse por datasets grandes
  • Forecasting estadístico real (ARIMA, Holt-Winters, Prophet) — no una regresión lineal JS aproximada
  • Plotly genera charts idénticos en todos los browsers — sin inconsistencias de Recharts
  • Plotly dark template integrado — los charts son bonitos por defecto, sin CSS extra
  • El backend ya existe (FastAPI) — solo se agregan routers, sin nueva infraestructura
  • Caché fácil en FastAPI con @lru_cache o Redis — queries caras se cachean
  • El frontend queda ultra-liviano: grid + modal + <Plot />
